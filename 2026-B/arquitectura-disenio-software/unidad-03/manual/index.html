0. Antes de empezar

Este manual construye el esqueleto ejecutable del proyecto de la Unidad 3. No implementa las seis funcionalidades del enunciado: implementa una de punta a punta —productos— con todas las capas, la seguridad y la resiliencia puestas. Repetir el patrón para carrito, pedidos y usuarios es entonces mecánico, y ese es el trabajo del equipo.

Cada paso tiene tres partes:

  • Qué hacer — la acción concreta.
  • Deberías ver — cómo compruebas que salió bien antes de seguir.
  • Si algo salió mal — el problema típico y su solución.

3. Crea la estructura hexagonal

Qué hacer. Dentro de src/main/java/co/edu/corhuila/techshopcloud/, crea esta estructura de paquetes:

  techshopcloud/
  ├── domain/                  ← el núcleo. NO importa nada de Spring
  │   ├── model/               Product, Order, User…
  │   └── exception/           InsufficientStockException…
  ├── application/             ← casos de uso y puertos
  │   ├── usecase/             ProductUseCase…
  │   └── port/
  │       ├── in/              lo que la aplicación ofrece
  │       └── out/             lo que la aplicación necesita
  ├── infrastructure/          ← adaptadores secundarios
  │   ├── persistence/         entidades JPA, repositorios
  │   ├── security/            JWT, filtros, configuración
  │   └── config/              beans, Resilience4j
  └── interfaces/              ← adaptadores primarios
      └── rest/                controladores y DTO

Deberías ver. Los paquetes vacíos en el árbol del proyecto.

Si algo salió mal. En IntelliJ, si un paquete no aparece, es porque está vacío y el árbol los colapsa: activa Compact Middle Packages en las opciones del panel.

Nota

La regla que hay que sostener todo el manual: una clase de domain no puede tener ningún import de Spring, JPA ni Jackson. Es la comprobación más rápida de que la arquitectura hexagonal está bien puesta, y es lo primero que se revisa al calificar.

5. Ahora el dominio

Qué hacer. Crea domain/exception/InsufficientStockException.java y domain/model/Product.java:

package co.edu.corhuila.techshopcloud.domain.model;

import co.edu.corhuila.techshopcloud.domain.exception.InsufficientStockException;
import java.math.BigDecimal;
import java.time.LocalDateTime;
import java.util.UUID;

public class Product {
    private final UUID id;
    private String name;
    private String description;
    private BigDecimal price;
    private String category;
    private int stockQuantity;
    private boolean active;
    private final LocalDateTime createdAt;
    private LocalDateTime updatedAt;

    public Product(String name, String description, BigDecimal price,
                   String category, int stockQuantity) {
        if (name == null || name.isBlank())
            throw new IllegalArgumentException("El nombre es obligatorio");
        if (price == null || price.signum() < 0)
            throw new IllegalArgumentException("El precio no puede ser negativo");
        if (stockQuantity < 0)
            throw new IllegalArgumentException("El inventario no puede ser negativo");

        this.id = UUID.randomUUID();
        this.name = name;
        this.description = description;
        this.price = price;
        this.category = category;
        this.stockQuantity = stockQuantity;
        this.active = true;
        this.createdAt = LocalDateTime.now();
        this.updatedAt = this.createdAt;
    }

    public boolean hasStock() { return stockQuantity > 0; }

    public void decreaseStock(int quantity) {
        if (quantity <= 0)
            throw new IllegalArgumentException("La cantidad debe ser positiva");
        if (stockQuantity < quantity)
            throw new InsufficientStockException(id, stockQuantity, quantity);
        this.stockQuantity -= quantity;
        this.updatedAt = LocalDateTime.now();
    }

    // getters; sin setters públicos de inventario: el estado se cambia
    // solo por métodos de negocio que protegen las invariantes.
    public UUID getId() { return id; }
    public String getName() { return name; }
    public BigDecimal getPrice() { return price; }
    public int getStockQuantity() { return stockQuantity; }
    public boolean isActive() { return active; }
}
package co.edu.corhuila.techshopcloud.domain.exception;

import java.util.UUID;

public class InsufficientStockException extends RuntimeException {
    public InsufficientStockException(UUID productId, int disponible, int solicitado) {
        super("Inventario insuficiente para %s: hay %d, se pidieron %d"
              .formatted(productId, disponible, solicitado));
    }
}

Ejecuta mvn test otra vez.

Deberías ver. Tests run: 4, Failures: 0, Errors: 0. Fase verde.

SíntomaSolución

Cuidado

Fíjate en que no hay setter de inventario. El enunciado del proyecto incluye product.setStockQuantity(0) en una de sus pruebas; si lo agregas, cualquiera puede dejar el inventario en un estado imposible sin pasar por la regla. Es mejor una prueba que construya el producto con el inventario que quiere.

package co.edu.corhuila.techshopcloud.application.usecase;

import co.edu.corhuila.techshopcloud.application.port.out.ProductRepositoryPort;
import co.edu.corhuila.techshopcloud.domain.model.Product;
import java.math.BigDecimal;
import java.util.*;

public class ProductUseCase {
    private final ProductRepositoryPort repository;

    public ProductUseCase(ProductRepositoryPort repository) {
        this.repository = repository;   // inyección por constructor: testeable
    }

    public Product createProduct(String name, String description, BigDecimal price,
                                 String category, int stock) {
        return repository.save(new Product(name, description, price, category, stock));
    }

    public Optional<Product> getProductById(UUID id) { return repository.findById(id); }

    public List<Product> getAllProducts() { return repository.findAll(); }

    public Product purchase(UUID id, int quantity) {
        Product p = repository.findById(id)
            .orElseThrow(() -> new NoSuchElementException("Producto no encontrado"));
        p.decreaseStock(quantity);      // la regla vive en el dominio
        return repository.save(p);
    }
}

package co.edu.corhuila.techshopcloud.infrastructure.persistence;

import co.edu.corhuila.techshopcloud.application.port.out.ProductRepositoryPort;
import co.edu.corhuila.techshopcloud.domain.model.Product;
import org.springframework.stereotype.Repository;
import java.util.*;

@Repository
public class JpaProductRepositoryAdapter implements ProductRepositoryPort {

    private final SpringDataProductRepository jpa;
    private final ProductMapper mapper;

    public JpaProductRepositoryAdapter(SpringDataProductRepository jpa, ProductMapper mapper) {
        this.jpa = jpa; this.mapper = mapper;
    }

    @Override public Product save(Product p) {
        return mapper.toDomain(jpa.save(mapper.toEntity(p)));
    }
    @Override public Optional<Product> findById(UUID id) {
        return jpa.findById(id).map(mapper::toDomain);
    }
    @Override public List<Product> findAll() {
        return jpa.findAll().stream().map(mapper::toDomain).toList();
    }
}
package co.edu.corhuila.techshopcloud.interfaces.rest;

@RestController

        var p = useCase.createProduct(r.name(), r.description(),

        return ResponseEntity.status(201).body(p);
    }
}

8. Seguridad: JWT y roles

Qué hacer. Crea el proveedor de tokens y la configuración de seguridad.

package co.edu.corhuila.techshopcloud.infrastructure.security;

import io.jsonwebtoken.*;
import io.jsonwebtoken.security.Keys;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;
import javax.crypto.SecretKey;
import java.nio.charset.StandardCharsets;
import java.util.*;

@Component
public class JwtTokenProvider {

    private final SecretKey key;
    private final long expirationMs;

    public JwtTokenProvider(@Value("${jwt.secret}") String secret,
                            @Value("${jwt.expiration-ms}") long expirationMs) {
        this.key = Keys.hmacShaKeyFor(secret.getBytes(StandardCharsets.UTF_8));
        this.expirationMs = expirationMs;
    }

    public String generateToken(String username, List<String> roles) {
        Date now = new Date();
        return Jwts.builder()
                .setSubject(username)
                .claim("roles", roles)
                .setIssuedAt(now)
                .setExpiration(new Date(now.getTime() + expirationMs))
                .signWith(key, SignatureAlgorithm.HS512)   // API 0.11+
                .compact();
    }

    public boolean validate(String token) {
        try {
            Jwts.parserBuilder().setSigningKey(key).build().parseClaimsJws(token);
            return true;
        } catch (JwtException | IllegalArgumentException e) {
            return false;
        }
    }

    public Claims claims(String token) {
        return Jwts.parserBuilder().setSigningKey(key).build()
                   .parseClaimsJws(token).getBody();
    }
}
package co.edu.corhuila.techshopcloud.infrastructure.security;

import org.springframework.context.annotation.*;
import org.springframework.security.config.annotation.method.configuration.EnableMethodSecurity;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.http.SessionCreationPolicy;
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.security.web.SecurityFilterChain;
import org.springframework.security.web.authentication.UsernamePasswordAuthenticationFilter;

@Configuration
@EnableMethodSecurity            // habilita @PreAuthorize
public class SecurityConfig {

    private final JwtAuthenticationFilter jwtFilter;
    public SecurityConfig(JwtAuthenticationFilter jwtFilter) { this.jwtFilter = jwtFilter; }

    @Bean
    public SecurityFilterChain chain(HttpSecurity http) throws Exception {
        return http
            .csrf(c -> c.disable())                       // API sin estado: no hay sesión
            .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(a -> a
                .requestMatchers("/api/auth/**").permitAll()
                .requestMatchers("/actuator/health").permitAll()
                .requestMatchers("/api/products/**").authenticated()
                .anyRequest().authenticated())
            .addFilterBefore(jwtFilter, UsernamePasswordAuthenticationFilter.class)
            .build();
    }

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();   // hash con sal, NO cifrado reversible
    }
}

package co.edu.corhuila.techshopcloud.infrastructure.payment;

import io.github.resilience4j.circuitbreaker.annotation.CircuitBreaker;
import io.github.resilience4j.retry.annotation.Retry;
import org.springframework.stereotype.Service;

@Service
public class PaymentAdapter {

    @Retry(name = "paymentService")
    @CircuitBreaker(name = "paymentService", fallbackMethod = "pagoDiferido")
    public PaymentResult charge(OrderId id, Money amount) {
        return gatewayClient.charge(id, amount);
    }

    // El fallback define QUÉ VE EL USUARIO cuando la pasarela no está.
    private PaymentResult pagoDiferido(OrderId id, Money amount, Throwable cause) {
        pendingPayments.enqueue(id, amount);
        return PaymentResult.pending("Pago en proceso; te confirmamos por correo");
    }
}

Deberías ver. En http://localhost:8080/actuator/health, un bloque circuitBreakers con el estado CLOSED.

Si algo salió mal. Si el fallback nunca se invoca, revisa su firma: debe tener los mismos parámetros que el método original más un Throwable al final. Es el error más frecuente con Resilience4j.

Cuidado

El archivo .env no se sube nunca al repositorio. Una credencial en el historial de Git sigue ahí aunque después la borres, y es exactamente el hallazgo de «configuración insegura» de la lista OWASP.

Tip

El enunciado pide más del 80 %, pero no todo cuenta igual. Cobertura alta en domain y application demuestra que las reglas están probadas; cobertura inflada con pruebas de getters sube el número y no prueba nada. Prioriza dominio y casos de uso.

12. Antes de entregar

  • Ninguna clase de domain importa Spring, JPA ni Jackson.
  • Las reglas de negocio se prueban sin base de datos y sin contexto de Spring.
  • Cobertura superior al 80 %, con domain y application altos.
  • La API responde 401 sin token y 403 con rol insuficiente.
  • Las contraseñas se guardan con BCrypt, no cifradas.
  • JWT_SECRET y la contraseña de la base llegan por variable de entorno.
  • .env está en .gitignore y no hay secretos en el historial.
  • El circuit breaker tiene fallback y su firma es correcta.
  • /actuator/health verifica la base de datos.
  • docker compose up --build levanta todo desde cero en una máquina limpia.
  • El contenedor no corre como root.
  • El manifiesto de Kubernetes tiene minReplicas: 2 y su HPA.

Nota

Peso de la rúbrica, para priorizar: arquitectura 30 %, funcionalidad 25 %, pruebas 20 %, seguridad y resiliencia 15 %, documentación 10 %. Este manual deja resueltos la arquitectura, las pruebas, la seguridad y la resiliencia —el 65 %—; la funcionalidad de las seis historias y la documentación son el trabajo del equipo.
