2. Síntesis

  • Entorno: SDK + IDE; Android Studio (nativo), Node + Ionic CLI (híbrido); emuladores y dispositivo real.
  • Lenguajes: Kotlin (nativo, null‑safe, val/var); TypeScript/React (Ionic).
  • Backend: API REST (GET/POST/PUT/DELETE), JSON, Express (express.json, res.json).
  • Frameworks: Ionic vs React Native vs Flutter; Ionic React = componentes + useState + rutas + Capacitor.

3. Ejercicios tipo parcial (con razonamiento)

1) ¿Qué método HTTP y ruta usarías para actualizar el producto 5? `PUT /productos/5`.

2) En Kotlin, ¿por qué val en vez de var cuando el dato no cambia? Inmutabilidad → menos errores.

3) ¿Qué imprime este componente al pulsar 3 veces?

const [n, setN] = useState(0);
<IonButton onClick={() => setN(n + 1)}>Clics: {n}</IonButton>

Muestra "Clics: 3" tras 3 pulsaciones (el estado redibuja).

4) ¿Por qué la app debe manejar errores al hacer fetch? La red puede fallar; hay que avisar al usuario.

5) Menciona una ventaja de Ionic React frente a hacer dos apps nativas. Una sola base de código → menor costo/tiempo.

Cuidado

En el parcial se evalúa leer y razonar código, no solo teoría.

4. Preparación

  • Modalidad: individual, teórico‑práctica. Temas: semanas 6–9.
  • Ten claro el flujo app ↔ API (fetch → JSON) y los componentes básicos de Ionic React.
