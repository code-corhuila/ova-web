1. Autenticación con tokens (JWT)

Nota

Tras iniciar sesión, el servidor devuelve un token (p. ej. JWT). La app lo guarda y lo envía en cada petición protegida (cabecera Authorization). El servidor lo valida sin guardar sesión.

const { token } = await (await fetch(API + "/login", {
  method: "POST", headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ correo, clave })
})).json();

const perfil = await fetch(API + "/perfil", {
  headers: { Authorization: "Bearer " + token }
});

Cuidado

Nunca guardes el token en un lugar inseguro ni lo publiques. Usa el almacenamiento seguro del dispositivo.

2. Consumo robusto de la API

Toda llamada debe manejar: carga, éxito y error (red caída, 401 no autorizado, 500 del servidor).

try {
  const resp = await fetch(url);
  if (!resp.ok) throw new Error("HTTP " + resp.status);
  return await resp.json();
} catch (e) {
  // mostrar mensaje y permitir reintento
}

3. Conectividad y offline

Nota

En móvil la red falla: túneles, datos agotados, wifi intermitente. Una app robusta detecta la conectividad, cachea datos localmente y sincroniza cuando vuelve la conexión.

EstrategiaIdea
Caché localGuardar la última respuesta para mostrarla offline
Cola de cambiosEncolar acciones y enviarlas al reconectar
Indicador de estadoAvisar "sin conexión" al usuario

4. Separación de responsabilidades

Centraliza el acceso a la API en un servicio (una capa), no repartido por las pantallas. Así el manejo de token, errores y URLs vive en un solo lugar (bajo acoplamiento).

5. Errores comunes

  • Repetir la URL y el manejo de token en cada pantalla (centraliza en un servicio).
  • No manejar el 401 (token vencido) → la app "se queda pegada".
  • Suponer conexión siempre disponible.
  • Guardar el token de forma insegura.
