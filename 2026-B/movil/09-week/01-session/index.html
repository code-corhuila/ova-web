Frameworks móviles híbridos (Ionic React)

Los frameworks híbridos permiten una sola base de código para Android e iOS. Comparamos Ionic, Flutter y React Native, y profundizamos en Ionic React —el énfasis del curso— construyendo pantallas con sus componentes y navegación.

1. Comparativa de híbridos

FrameworkLenguajeEnfoque
IonicWeb (React/Angular/Vue) + CapacitorWeb components sobre WebView; muy productivo
React NativeJavaScript/TypeScript (React)Componentes nativos reales
FlutterDartMotor de render propio, UI muy fluida

Nota

Los tres logran multiplataforma. En el curso usamos Ionic React: aprovechas React + componentes listos (IonButton, IonList…) y Capacitor para acceder al hardware.

2. Un componente de página en Ionic React

const HomePage: React.FC = () => (
  <IonPage>
    <IonHeader><IonToolbar><IonTitle>Inicio</IonTitle></IonToolbar></IonHeader>
    <IonContent className="ion-padding">
      <IonButton expand="block">Comenzar</IonButton>
    </IonContent>
  </IonPage>
);

Nota

Todo se construye con componentes: piezas reutilizables (IonPage, IonHeader, IonButton) que se combinan como bloques.

3. Estado con hooks (useState)

Nota

Un hook useState guarda datos que cambian y provocan que la pantalla se redibuje al actualizarse.

const Contador: React.FC = () => {
  const [n, setN] = useState(0);
  return <IonButton onClick={() => setN(n + 1)}>Clics: {n}</IonButton>;
};

4. Navegación entre páginas

Ionic React usa rutas (React Router). Se define qué componente muestra cada ruta y se navega con enlaces o programáticamente:

/ (Home)  →  /detalle/:id  →  /perfil

5. Errores comunes

  • Manipular el DOM directamente en vez de usar el estado (React re‑renderiza solo).
  • Olvidar la key al renderizar listas.
  • Poner toda la app en un solo componente gigante (divide en componentes).
  • No probar en dispositivo real con Capacitor.
