Optimización y testing

Antes de publicar, la app debe ser rápida y confiable. Esta sesión cubre optimización de rendimiento y estrategias de pruebas (unitarias, de integración y de interfaz) para entregar con calidad y sin sorpresas.

1. ¿Por qué optimizar?

En móvil los recursos son limitados (batería, memoria, red). Una app lenta o que consume mucho se desinstala. Optimizar mejora la experiencia y la retención.

2. Técnicas de optimización

ÁreaTécnica
Listas grandesRenderizado eficiente / virtualización; usar key
ImágenesComprimir, tamaños adecuados, carga diferida
RedCachear, paginar resultados, evitar llamadas repetidas
RenderEvitar cálculos y renders innecesarios (memoizar)

Tip

Mide antes de optimizar. Usa las herramientas de desempeño del navegador/Android Studio para encontrar el cuello de botella real, no el supuesto.

3. Tipos de pruebas

Nota

Unitarias: prueban una función/componente aislado. De integración: varias piezas juntas (p. ej. servicio + API). De interfaz (E2E): simulan al usuario navegando la app.

Muchas unitarias  →  algunas de integración  →  pocas E2E   (pirámide de pruebas)

4. Una prueba unitaria básica

import { conIva } from "./precio";

test("conIva agrega 19%", () => {
  expect(conIva(100)).toBe(119);
});

Nota

Las pruebas automatizadas son una red de seguridad: al cambiar el código, detectan de inmediato si algo se rompió (clave para refactorizar con confianza).

5. Errores comunes

  • Optimizar "a ciegas" sin medir el cuello de botella.
  • No usar key en listas (renders incorrectos/lentos).
  • Cero pruebas → cada cambio es una apuesta.
  • Solo pruebas E2E (lentas y frágiles) sin base de unitarias.
