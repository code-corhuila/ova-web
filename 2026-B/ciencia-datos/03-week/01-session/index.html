Ecosistema de Big Data

Procesar grandes volúmenes exige una arquitectura, no una sola herramienta. Esta sesión presenta el ecosistema de Big Data: dónde se guardan los datos (lago vs almacén), cómo se procesan (por lotes vs en tiempo real) y qué piezas componen un flujo típico.

1

Distinguir data lake y data warehouse.

2

Diferenciar procesamiento por lotes y en streaming.

3

Reconocer componentes de una arquitectura de datos.

4

Ubicar herramientas del ecosistema (Hadoop, Spark, etc.).

1. ¿Dónde se guardan los datos?

RepositorioQué guardaCuándo
Data Warehouse (almacén)Datos estructurados y ya procesadosReportes y BI
Data Lake (lago)Datos crudos de cualquier tipoExploración, ML, futuro uso

Nota

El lago guarda todo tal cual llega (barato, flexible); el almacén guarda datos limpios y modelados para consultas rápidas. Muchas empresas usan ambos.

2. ¿Cómo se procesan?

Nota

Por lotes (batch): se procesan grandes bloques cada cierto tiempo (p. ej. cada noche). En tiempo real (streaming): se procesan a medida que llegan (p. ej. telemetría de sensores).

Batch:     [datos] --(cada noche)--> [proceso] --> resultados
Streaming: [dato][dato][dato]...  --> [proceso continuo] --> alertas al instante

3. Piezas de una arquitectura de datos

Fuentes → Ingesta → Almacenamiento → Procesamiento → Análisis/BI
(sensores, (Kafka,   (lake/warehouse) (Spark, dbt)   (Power BI, Python)
 apps, BD)  APIs)
  • Fuentes: de dónde vienen los datos.
  • Ingesta: cómo entran (APIs, colas como Kafka).
  • Almacenamiento: lake/warehouse.
  • Procesamiento: limpiar/transformar (Spark, dbt).
  • Análisis/BI: visualizar y decidir.

4. Herramientas del ecosistema (panorama)

  • Hadoop: almacenamiento y procesamiento distribuido (clásico).
  • Spark: procesamiento distribuido rápido, en memoria.
  • Kafka: ingesta de datos en tiempo real (colas de eventos).
  • Airflow / n8n: orquestación de flujos (ETL).
  • dbt: transformación de datos en el almacén.

Tip

No necesitas dominar todas. Entiende qué problema resuelve cada una; elegirás según el caso.

5. Errores comunes

  • Convertir el lago en un "pantano" (datos sin catálogo ni gobierno).
  • Usar streaming cuando basta batch (complejidad innecesaria).
  • Comprar herramientas antes de entender el flujo de datos.
  • No pensar en la calidad desde la ingesta.
