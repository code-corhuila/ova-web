Optimización de consultas y métricas (SQL y DAX)

Cuando los datos crecen, una consulta lenta cuesta tiempo y dinero. Esta sesión cubre cómo escribir consultas eficientes (índices, filtros) y cómo crear métricas con DAX en Power BI.

1. ¿Por qué optimizar?

Nota

Con pocos datos todo es rápido; con millones de filas, una consulta mal escrita puede tardar minutos. Optimizar = obtener el mismo resultado usando menos recursos.

2. Buenas prácticas en SQL

  • Filtrar temprano (WHERE) y traer solo las columnas necesarias (evitar SELECT *).
  • Usar índices en columnas de búsqueda/join (aceleran mucho la lectura).
  • Evitar funciones sobre columnas en el WHERE (impiden usar el índice).
  • Preferir JOIN a subconsultas repetidas.
SELECT * FROM ventas WHERE YEAR(fecha) = 2026;   -- función sobre columna
SELECT id, total FROM ventas
WHERE fecha >= '2026-01-01' AND fecha < '2027-01-01';  -- usa índice en fecha

Nota

Un índice es como el índice de un libro: permite ir directo al dato sin leerlo todo.

3. DAX en Power BI

Nota

DAX (Data Analysis Expressions) es el lenguaje de fórmulas de Power BI para crear medidas y columnas calculadas (sumas, promedios, % del total, comparaciones entre periodos).

Total Ventas = SUM(Ventas[Total])
Ventas 2026 = CALCULATE([Total Ventas], YEAR(Ventas[Fecha]) = 2026)

4. Columna calculada vs. medida

Columna calculadaMedida
Cuándo se calculaAl cargar (fila por fila)Al vuelo (según filtros)
Ocupa espacioSíNo
UsoCategorizar filasAgregar (sumas, %, KPIs)

Tip

Para KPIs y agregados usa medidas; para clasificar filas, columna calculada.

5. Errores comunes

  • SELECT * cuando solo necesitas 2 columnas.
  • Funciones sobre la columna filtrada (rompen el índice).
  • Confundir columna calculada con medida en DAX.
  • No medir: optimizar sin comparar antes/después.
