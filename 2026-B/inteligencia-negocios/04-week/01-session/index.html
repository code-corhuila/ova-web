El modelo estrella — hechos y dimensiones

El modelo estrella es la forma en que el BI organiza los datos para analizarlos con facilidad. Esta sesión define las tablas de hechos y de dimensiones, muestra cómo se conectan en forma de estrella y por qué este diseño hace que las preguntas de negocio se respondan casi solas.

1. El problema que resuelve el modelo estrella

Los datos operativos vienen partidos en muchas tablas normalizadas: cómodo para escribir, incómodo para analizar. El modelo dimensional los reorganiza pensando en cómo hace preguntas el negocio: "quiero ver las ventas (una medida) por producto, tiempo y tienda (unas dimensiones)".

Nota

Modelo estrella (star schema). Diseño de datos para análisis compuesto por una tabla de hechos central rodeada de tablas de dimensión. Su forma —un centro con radios— le da el nombre. Es el modelo dominante en BI por su simplicidad y velocidad.

2. Tabla de hechos y tablas de dimensión

Nota

Tabla de hechos. Guarda los eventos medibles del negocio (una venta, un despacho) y sus medidas numéricas (cantidad, precio, total). Es larga (muchas filas) y contiene las claves que la conectan a las dimensiones.

Nota

Tabla de dimensión. Guarda el contexto por el cual queremos analizar: quién, qué, cuándo, dónde. Contiene atributos descriptivos (nombre del producto, categoría, ciudad, mes). Es más corta y ancha.

              ┌───────────────┐
              │  DIM_TIEMPO   │
              │ fecha, mes,   │
              │ trimestre,año │
              └──────┬────────┘
                     │
 ┌────────────┐   ┌──┴───────────┐   ┌───────────────┐
 │DIM_PRODUCTO│───│ HECHOS_VENTAS│───│  DIM_CLIENTE  │
 │ nombre,    │   │ id_producto  │   │ nombre, ciudad│
 │ categoría  │   │ id_cliente   │   │ segmento      │
 └────────────┘   │ id_tiempo    │   └───────────────┘
                  │ cantidad     │
                  │ total  (▲)   │  (▲) = medidas
                  └──────────────┘

3. Medidas frente a atributos

Distinguirlos es la clave del modelado dimensional:

MedidaAtributo
Dónde viveTabla de hechosTabla de dimensión
Qué esUn número que se agregaUn texto/categoría que describe
Se usa paraSumar, promediar, contarFiltrar, agrupar, "cortar"
Ejemplototal = 320000categoría = "Pantallas"

Tip

Prueba rápida: si tiene sentido sumarlo, es una medida (va en hechos). Si tiene sentido agrupar por ello, es un atributo (va en una dimensión). "Ventas por categoría": ventas = medida, categoría = atributo.

4. Por qué la estrella facilita el análisis

  • Pocas uniones: desde los hechos, cada dimensión está a un solo salto. Consultas simples y rápidas.
  • Lenguaje del negocio: las dimensiones son las palabras que usa la gente (producto, mes, ciudad).
  • Flexibilidad: una misma estrella responde muchas preguntas solo cambiando por qué dimensión agrupas.

Cuidado

No confundas con el copo de nieve (snowflake): si cada dimensión se parte a su vez en subtablas, ganas normalización pero pierdes simplicidad. En BI básico se prefiere la estrella por su claridad.

5. Ejemplo trabajado: diseñar una estrella de ventas

Pregunta de negocio: "¿Cuánto vendimos por categoría, ciudad y mes?".

  1. Hecho: cada línea de venta. Medidas: cantidad, total.
  2. Dimensiones (las palabras después de "por"): Producto (→ categoría), Cliente (→ ciudad), Tiempo (→ mes).
  3. Conectar: la tabla de hechos guarda id_producto, id_cliente, id_tiempo que apuntan a cada dimensión.

Con eso, "ventas por categoría" = sumar total agrupando por el atributo categoría de la dimensión Producto. Sin reprogramar nada, "ventas por ciudad" solo cambia la dimensión.

6. Errores comunes

  • Meter medidas (números para sumar) dentro de las dimensiones.
  • Meter atributos descriptivos en la tabla de hechos.
  • Olvidar la dimensión Tiempo: casi todo análisis de negocio se ve "en el tiempo".
  • Sobre-normalizar hasta convertir la estrella en un copo de nieve innecesario.
