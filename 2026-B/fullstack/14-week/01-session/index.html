Contenedores con Docker

"En mi máquina sí funciona" deja de ser excusa con Docker. Un contenedor empaqueta tu aplicación con todo lo que necesita para correr igual en cualquier lugar. Esta sesión explica imágenes, contenedores y cómo empaquetar tu app.

1. ¿Qué problema resuelve Docker?

Nota

Docker empaqueta la aplicación con su entorno (versión de Java/Node, librerías, configuración) en un contenedor que corre igual en cualquier máquina. Elimina el "en mi equipo funciona" y facilita el despliegue.

2. Imagen vs contenedor

Nota

Una imagen es la plantilla (la app + su entorno, congelada). Un contenedor es una instancia en ejecución de esa imagen. De una imagen puedes correr muchos contenedores.

Dockerfile  --build-->  Imagen  --run-->  Contenedor (en ejecución)
 (receta)               (plantilla)        (instancia)

3. Dockerfile

FROM eclipse-temurin:21-jre
COPY target/app.jar /app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "/app.jar"]
docker build -t tienda-api .      // construir la imagen
docker run -p 8080:8080 tienda-api // correr el contenedor

4. Varios servicios juntos

Nota

Una app fullstack suele tener frontend, backend y base de datos. Docker Compose levanta varios contenedores juntos con un solo archivo (docker-compose.yml), conectándolos entre sí.

Tip

Empaquetar en contenedores hace el despliegue (siguiente sesión) mucho más simple: el servidor solo necesita Docker, no instalar Java/Node a mano.

5. Errores comunes

  • Confundir imagen (plantilla) con contenedor (instancia).
  • No exponer el puerto (EXPOSE/-p) y no poder acceder.
  • Meter datos que cambian dentro de la imagen (usar volúmenes).
  • Imágenes enormes por no partir de una base adecuada.
