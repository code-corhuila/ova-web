Frontend con framework (Angular / React)

Escribir una SPA solo con JavaScript se vuelve difícil al crecer. Los frameworks (Angular) y librerías (React) organizan la interfaz en componentes reutilizables, con enrutamiento y manejo de estado. Esta sesión da el panorama para elegir y empezar.

1. ¿Por qué un framework?

Nota

Un framework/librería de frontend organiza la SPA en componentes (piezas reutilizables de interfaz), sincroniza automáticamente los datos con la vista (estado) y gestiona la navegación (enrutamiento). Evita manipular el DOM "a mano".

2. Componentes

Un componente encapsula estructura + estilo + lógica de una parte de la UI (una tarjeta, una lista, un formulario) y se reutiliza.

function Producto({ nombre, precio }) {
  return <li>{nombre} — ${precio}</li>;
}
@Component({ selector: 'app-producto', template: '<li>{{nombre}} — {{precio}}</li>' })
export class ProductoComponent { @Input() nombre!: string; @Input() precio!: number; }

3. Estado

Nota

El estado son los datos que la vista muestra. Cuando el estado cambia, el framework re-renderiza la vista automáticamente (no actualizas el DOM tú).

const [productos, setProductos] = useState([]);
useEffect(() => { fetch(url).then(r => r.json()).then(setProductos); }, []);

4. Enrutamiento

El router muestra distintos componentes según la URL (/productos, /productos/1) sin recargar la página: es lo que hace "de una sola página" a la SPA.

Tip

No hay "mejor" absoluto. En este curso el énfasis es entender componentes, estado y enrutamiento; el proyecto puede entregarse en Angular o React.

6. Errores comunes

  • Manipular el DOM manualmente peleando con el framework.
  • Duplicar estado en varios lugares (fuente única de verdad).
  • Componentes gigantes que hacen de todo (mejor pequeños y reutilizables).
  • Olvidar que la SPA sigue necesitando una API para los datos.
