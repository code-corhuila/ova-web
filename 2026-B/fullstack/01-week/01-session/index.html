Introducción al desarrollo fullstack, SCRUM y Git

Un desarrollador fullstack construye la aplicación completa: la parte que ve el usuario (frontend) y la parte que vive en el servidor (backend). Esta sesión te da el mapa del curso, la forma ágil de trabajar (SCRUM) y la herramienta que usarás siempre para versionar y entregar tu código (Git).

1. ¿Qué es "fullstack"?

Nota

Fullstack = dominar las dos capas de una aplicación web: el frontend (interfaz que usa la persona, en el navegador) y el backend (lógica y datos en el servidor). Entre ambos se comunican mediante una API.

[ Navegador ]        HTTP (JSON)        [ Servidor ]        [ Base de datos ]
  Frontend    <----------------------->   Backend    <----->   (tablas)
  HTML/CSS/JS        pide / responde     API REST            guarda / lee

2. Las capas de una aplicación

CapaQué haceTecnologías del curso
FrontendLo que ve y toca el usuarioHTML, CSS, JavaScript, Angular/React
BackendLógica de negocio y APIJava, Spring Boot
DatosAlmacena la informaciónBase de datos relacional (JPA)

Tip

El frontend pide datos; el backend responde. Separar capas permite que cada una evolucione sin romper a la otra.

3. Trabajar ágil: SCRUM

Nota

SCRUM organiza el trabajo en sprints (iteraciones cortas) que entregan algo funcional. Roles: Product Owner (prioriza), Scrum Master (facilita), Equipo (construye). Artefactos: product backlog, sprint backlog e incremento.

  • Historia de usuario: Como [rol], quiero [acción] para [beneficio].
  • Tablero: Por hacer → En progreso → Hecho.
  • El curso avanzará por cortes, como sprints, con entregas por corte.

4. Git y GitHub: versionar y entregar

Nota

Git guarda la historia de tu código (puedes volver atrás y trabajar en equipo). GitHub aloja el repositorio en la nube. En este curso entregas por GitHub, en tu fork del repositorio de la clase.

git clone <url-de-tu-fork>     // traer el repo a tu equipo
git add .                      // preparar los cambios
git commit -m "Entrega semana 1"
git push                       // subirlos a GitHub
1. Fork del repositorio de la clase
2. Clonar tu fork
3. Trabajar en la carpeta de la semana (NN-week/)
4. add -> commit -> push

Tip

Crea tu repo de perfil (usuario/usuario) con el bloque CONFIG (FULL_NAME + GITHUB_USER). Sin él, los scripts del curso no detectan tus entregas. Ver el Manual de Entrega por GitHub en Información importante.

5. Errores comunes

  • Confundir frontend con backend (la interfaz no guarda los datos: los pide).
  • Querer "hacerlo todo perfecto" en vez de iterar por sprints.
  • No hacer commit seguido → se pierde trabajo.
  • Subir cambios fuera de la carpeta de la semana.
