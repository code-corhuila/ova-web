Despliegue (local y en la nube, AWS) y proyecto final

El último paso: llevar la aplicación a la nube para que cualquiera la use. Esta sesión explica el despliegue local vs. cloud (AWS) y consolida el proyecto final fullstack de extremo a extremo.

Diferenciar despliegue local y en la nube.

2

Conocer opciones de despliegue en AWS.

3

Consolidar el proyecto final fullstack.

1. ¿Qué es desplegar?

Nota

Desplegar es poner la aplicación en un servidor accesible para los usuarios. Local = corre en tu equipo (para probar); nube = corre en un servidor remoto disponible 24/7.

2. Local vs nube

LocalNube (AWS)
AccesoSolo tu equipoDesde internet
UsoDesarrollo/pruebasProducción
CostoGratisSegún recursos

3. Opciones de despliegue en AWS

Nota

Con la app en contenedores (sesión anterior), desplegar es más simple. Opciones comunes: una máquina virtual (EC2) con Docker, servicios de contenedores gestionados, o alojar el frontend estático en S3 y el backend en un servicio de cómputo.

Frontend (build) ─► alojamiento estático (S3 / hosting)
Backend (contenedor) ─► servidor cloud (EC2 con Docker)
Base de datos ─► servicio de BD gestionado

4. Variables de entorno y configuración

Tip

En producción, no quemes claves/URLs en el código: usa variables de entorno (URL de la BD, secreto del JWT, origen del frontend para CORS). Cambian entre local y nube.

5. El proyecto final

Nota

El proyecto integra todo el curso en una app fullstack funcional: frontend (SPA con framework), backend (API REST en capas), base de datos, seguridad (JWT), pruebas, contenedores y despliegue.

Estructura sugerida del entregable (por GitHub):

  1. Frontend: SPA que consume la API (login + al menos un CRUD).
  2. Backend: API REST en capas con persistencia y JWT.
  3. Calidad: al menos una prueba de cada capa; Docker.
  4. README: descripción, cómo ejecutar, capturas y (opcional) URL desplegada.

6. Errores comunes

  • Quemar claves/URLs en el código en vez de variables de entorno.
  • Desplegar sin haber probado ni contenerizado.
  • Olvidar habilitar CORS para el dominio real del frontend.
  • README ausente: nadie sabe cómo correr el proyecto.
