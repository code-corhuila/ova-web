Servicios y controladores REST (service, controller, endpoints)

Ahora exponemos los datos al mundo. El controller define los endpoints REST (URLs + método HTTP) que el frontend consume; el service aplica la lógica. Construiremos un CRUD REST completo.

1. ¿Qué es una API REST?

Nota

REST expone recursos mediante URLs y métodos HTTP: GET /productos (listar), GET /productos/1 (uno), POST /productos (crear), PUT /productos/1 (actualizar), DELETE /productos/1 (borrar). Devuelve JSON.

2. El controller

@RestController
@RequestMapping("/productos")
public class ProductoController {
  private final ProductoService service;
  public ProductoController(ProductoService service) { this.service = service; }

  @GetMapping
  public List<Producto> listar() { return service.listar(); }

  @PostMapping
  public Producto crear(@RequestBody Producto p) { return service.guardar(p); }
}

Nota

@RestController devuelve JSON; @RequestMapping fija la ruta base; @GetMapping/@PostMapping mapean el método HTTP; @RequestBody convierte el JSON recibido en objeto.

3. CRUD REST completo

@GetMapping("/{id}")
public Producto uno(@PathVariable Long id) { return service.buscar(id); }

@DeleteMapping("/{id}")
public void borrar(@PathVariable Long id) { service.eliminar(id); }

4. Buenas prácticas REST

Tip

Usa sustantivos en plural para los recursos (/productos), el método HTTP para la acción (no /crearProducto), y códigos de estado correctos (200 OK, 201 creado, 404 no encontrado).

5. Errores comunes

  • Poner verbos en la URL (/getProductos) en vez de usar el método HTTP.
  • Meter lógica de negocio en el controller (va en el service).
  • No validar la entrada del @RequestBody.
  • Devolver siempre 200 aunque haya error.
