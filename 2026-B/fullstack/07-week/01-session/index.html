Capa de datos — entity y repository (JPA)

El backend necesita guardar y leer datos. Con JPA/Spring Data, una clase Java (entity) se mapea a una tabla y un repository te da las operaciones (guardar, listar, buscar, borrar) casi sin escribir SQL.

1

Mapear una entidad a una tabla con JPA.

2

Usar un repository para las operaciones CRUD.

3

Entender el mapeo objeto-relacional (ORM).

1. Mapeo objeto-relacional (ORM)

Nota

Un ORM hace corresponder clases ↔ tablas y objetos ↔ filas. JPA es el estándar de Java para ORM; Spring Data JPA lo hace muy simple. Así trabajas con objetos y la librería genera el SQL.

2. La entity

@Entity
public class Producto {
  @Id @GeneratedValue
  private Long id;
  private String nombre;
  private double precio;
  // getters y setters
}

Nota

@Entity marca la clase como tabla; @Id es la clave primaria; @GeneratedValue autogenera el id. Cada atributo es una columna.

3. El repository

public interface ProductoRepository
        extends JpaRepository<Producto, Long> {
  List<Producto> findByNombreContaining(String texto);
}

Nota

Al extender JpaRepository obtienes gratis: save(), findAll(), findById(), deleteById(). Y puedes declarar consultas por nombre de método (findByNombre...) sin escribir SQL.

4. CRUD desde el service

@Service
public class ProductoService {
  private final ProductoRepository repo;
  public ProductoService(ProductoRepository repo) { this.repo = repo; }

  public List<Producto> listar() { return repo.findAll(); }
  public Producto guardar(Producto p) { return repo.save(p); }
}

Tip

CRUD = Create, Read, Update, Delete. save() sirve para crear y actualizar; findAll/findById para leer; deleteById para borrar.

5. Errores comunes

  • Olvidar @Entity o @Id (JPA no mapea la clase).
  • Poner la lógica de datos en el controller en vez del service/repository.
  • No usar los métodos gratuitos de JpaRepository y reinventarlos.
  • Exponer la entity tal cual cuando conviene un DTO (se ve más adelante).
