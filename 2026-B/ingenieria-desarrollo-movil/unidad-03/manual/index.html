El hito H3 en orden de ejecución, con la app de referencia Bitácora de Campo como ejemplo trabajado. 1. Plugins como adaptadores

El mínimo 7 pide dos plugins nativos detrás de un puerto. En la referencia son la cámara y la geolocalización, y el patrón tiene tres piezas: un puerto que habla el idioma del dominio, un adaptador que es el único archivo que importa el plugin y un registro en la raíz de composición que une los dos.

1.1 El puerto, en el idioma del dominio

Qué hacer. Declara una interfaz de TypeScript puro por capacidad, sin un solo import de Angular ni de Capacitor. El error de permiso también es del dominio: hereda de ErrorDominio, que vive en core/errores/ y tampoco importa frameworks.

/**
 * Puerto: capacidad de tomar una foto. TypeScript puro.
 * El caso de uso CapturarEvidencia depende de esta interfaz, nunca del plugin.
 */
export interface Camara {
  /**
   * Abre la cámara y devuelve la foto como data URL (`data:image/jpeg;base64,...`).
   * @throws PermisoDenegadoError si la persona niega el permiso.
   */
  tomarFoto(): Promise<string>;
}
export interface Coordenadas {
  readonly lat: number;
  readonly lng: number;
}

/** Puerto: posición actual del dispositivo. TypeScript puro. */
export interface Ubicacion {
  /**
   * @throws PermisoDenegadoError si la persona niega el permiso.
   * @throws Error si el GPS está apagado o no responde a tiempo.
   */
  obtenerActual(): Promise<Coordenadas>;
}
import { ErrorDominio } from '../errores/errores-dominio';

export type RecursoNativo = 'cámara' | 'ubicación';

/** La persona negó (o tiene negado) un permiso del sistema. TypeScript puro: lo usa domain/. */
export class PermisoDenegadoError extends ErrorDominio {
  readonly codigo = 'PERMISO_DENEGADO';

  constructor(readonly recurso: RecursoNativo) {
    super(`Sin permiso de ${recurso}. Actívalo en Ajustes > Aplicaciones > Bitácora de Campo > Permisos.`);
  }
}

Deberías ver. Tres archivos sin dependencias externas. Los @throws del comentario son parte del contrato: le dicen al caso de uso qué errores puede esperar.

1.2 El adaptador: el único archivo que conoce el plugin

Qué hacer. Instala los plugins y sincroniza el proyecto nativo:

npm i @capacitor/camera @capacitor/geolocation
npx cap sync android

Luego implementa cada puerto con su plugin. El adaptador traduce el mundo del plugin (checkPermissions, PermissionState, Position) al del puerto (una foto, unas coordenadas o un PermisoDenegadoError).

import { Capacitor } from '@capacitor/core';
import { Camera, CameraDirection } from '@capacitor/camera';
import { Camara } from './camara.port';
import { PermisoDenegadoError } from './permiso-denegado.error';

/**
 * Adaptador del puerto Camara sobre @capacitor/camera 8.x (API nueva `takePhoto`, desde 8.1).
 *
 * Permiso just-in-time: se verifica y se pide JUSTO antes de abrir la cámara, cuando la persona
 * pulsó «Tomar foto», no al iniciar la app. En Android el plugin no declara el permiso CAMERA
 * (usa el intent del sistema) y `checkPermissions` responde `granted`; en iOS sí se pide.
 */
export class CamaraCapacitor implements Camara {
  async tomarFoto(): Promise<string> {
    if (Capacitor.isNativePlatform()) {
      let estado = await Camera.checkPermissions();
      if (estado.camera === 'prompt' || estado.camera === 'prompt-with-rationale') {
        estado = await Camera.requestPermissions({ permissions: ['camera'] });
      }
      if (estado.camera === 'denied') throw new PermisoDenegadoError('cámara');
    }

    const foto = await Camera.takePhoto({
      quality: 60,
      targetWidth: 1024,
      targetHeight: 1024,
      correctOrientation: true,
      cameraDirection: CameraDirection.Rear,
      includeMetadata: true,
    });
    if (!foto.thumbnail) throw new Error('La cámara no devolvió imagen.');
    // En nativo `thumbnail` es una versión reducida (suficiente como evidencia y liviana para la API);
    // en web es la imagen completa. Android/iOS pueden reportar 'jpg' en vez de 'jpeg'.
    const formato = (foto.metadata?.format ?? 'jpeg').replace('jpg', 'jpeg');
    return `data:image/${formato};base64,${foto.thumbnail}`;
  }
}
export class UbicacionCapacitor implements Ubicacion {
  async obtenerActual(): Promise<Coordenadas> {
    if (Capacitor.isNativePlatform()) {
      let estado = await Geolocation.checkPermissions(); // lanza si los servicios de ubicación están apagados
      if (estado.location === 'prompt' || estado.location === 'prompt-with-rationale') {
        estado = await Geolocation.requestPermissions({ permissions: ['location'] });
      }
      if (estado.location === 'denied') throw new PermisoDenegadoError('ubicación');
    }

    const posicion = await Geolocation.getCurrentPosition({ enableHighAccuracy: true, timeout: 10_000, maximumAge: 30_000 });
    return { lat: posicion.coords.latitude, lng: posicion.coords.longitude };
  }
}

Cuatro decisiones del adaptador que conviene repetir en tu proyecto:

DecisiónPor qué
Capacitor.isNativePlatform() antes de pedir permisosEn el navegador requestPermissions no existe; la misma app corre en ng serve sin romperse
prompt y prompt-with-rationale se tratan igualLos dos significan «todavía se puede preguntar»; el segundo indica que ya hubo una negativa
Foto reducida en el origen (quality 60, 1024 px)La evidencia viaja a la API y se guarda en caché: una foto completa la volvería pesada
Tiempo límite explícito en el GPS (10 s)Sin límite, un GPS sin señal deja la pantalla esperando indefinidamente

1.3 Registro en la raíz de composición

Qué hacer. Une puerto y adaptador con un InjectionToken y construye el caso de uso en la raíz de composición (core/di/), que es el único lugar que conoce a la vez el dominio y la infraestructura. El caso de uso se registra en la ruta de la feature, así solo existe mientras se usa.

import { InjectionToken } from '@angular/core';
import { Camara } from './camara.port';
import { CamaraCapacitor } from './camara-capacitor';
import { Ubicacion } from './ubicacion.port';
import { UbicacionCapacitor } from './ubicacion-capacitor';

/** Puerto Camara → adaptador Capacitor. Las pruebas lo reemplazan por una cámara falsa. */
export const CAMARA = new InjectionToken<Camara>('CAMARA', {
  providedIn: 'root',
  factory: () => new CamaraCapacitor(),
});

/** Puerto Ubicacion → adaptador Capacitor. */
export const UBICACION = new InjectionToken<Ubicacion>('UBICACION', {
  providedIn: 'root',
  factory: () => new UbicacionCapacitor(),
});
    { provide: CapturarEvidencia, useFactory: () => new CapturarEvidencia(inject(CAMARA), inject(UBICACION)) },
  {
    path: 'visitas',

    children: [
      {
        path: '',

provideVisitas() construye así los seis casos de uso de la feature, y la ruta visitas los registra junto con su guard. Cada pantalla hija se carga con loadComponent, lo que también aporta al rendimiento (sección 5.2).

Deberías ver. El plugin aparece solo en su adaptador. Compruébalo desde la raíz:

grep -rln "@capacitor/camera\|@capacitor/geolocation" src/app
# esperado: src/app/core/nativo/camara-capacitor.ts y src/app/core/nativo/ubicacion-capacitor.ts

Si algo salió mal. NullInjectorError: No provider for CapturarEvidencia indica que la página quedó fuera de la ruta que registra provideVisitas(). Si en Android aparece «plugin is not implemented on android», faltó npx cap sync android después de instalar el plugin.

La OVA y la referencia ubican los puertos en lugares distintos. La OVA los pone dentro de la feature (features/visitas/domain/ y data/); la referencia los deja en core/nativo/ porque cámara y ubicación pueden servir a más de una feature. Las dos opciones respetan la regla de dependencias. Escojan una, regístrenla en un ADR y apliquen la misma en toda la app.

2. Permisos just-in-time

Un permiso se pide cuando la persona toca la acción que lo necesita, nunca al abrir la app ni «por si acaso». En la referencia ese momento es el botón «Tomar foto y ubicación» del formulario de visita.

2.1 El flujo tal como lo implementa la referencia

  Toca «Tomar foto y ubicación»            ← momento de uso: aquí, no al abrir la app
             │
  VisitaFormViewModel.tomarEvidencia()     capturando: true
             │
  CapturarEvidencia.ejecutar()             el dominio solo conoce los puertos
             │
  1 ─ CamaraCapacitor.tomarFoto()
        checkPermissions ── prompt ──► requestPermissions (diálogo del sistema)
             ├── denied ──► PermisoDenegadoError('cámara') ──► SE PROPAGA
             │                 └──► estado.error → <ion-text role="alert">   (no hay foto)
             ▼ granted
        Camera.takePhoto() ──► foto
             │
  2 ─ UbicacionCapacitor.obtenerActual()   (solo si ya hay foto)
        checkPermissions ── prompt ──► requestPermissions
             ├── denied ──► PermisoDenegadoError('ubicación') ──┐
             ├── GPS apagado o tiempo agotado ──► Error ──────────┤ SE ABSORBE
             │                                                    └──► { foto, ubicacion: null, aviso }
             ▼ granted                                                  → <ion-note role="status">
        getCurrentPosition() ──► { foto, ubicacion, aviso: null }

El orden importa: primero la foto, que es obligatoria. Si la persona niega la cámara, la app no le pide además la ubicación.

2.2 Declarar en Android

Qué hacer. Declara en android/app/src/main/AndroidManifest.xml solo lo que el README de cada plugin exige para el uso que le das. Este es el bloque de permisos de la referencia:

    <!-- Permisos (mínimos; los peligrosos se piden just-in-time desde core/nativo/) -->
    <uses-permission android:name="android.permission.INTERNET" />

    <!-- @capacitor/geolocation (README del plugin, sección Android): ubicación aproximada y precisa. -->
    <uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
    <uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
    <!-- La ubicación es «mejor esfuerzo»: no se exige GPS para instalar la app. -->
    <uses-feature android:name="android.hardware.location.gps" android:required="false" />

    <!-- @capacitor/camera (README, sección Android): no requiere permisos porque no usamos
         saveToGallery; la foto se toma con el intent del sistema. Por eso NO se declara CAMERA. -->
</manifest>

Deberías ver. Tras compilar el release, el manifiesto fusionado (android/app/build/outputs/logs/manifest-merger-release-report.txt) muestra los permisos que aportan los plugins. En la referencia aparece además ACCESS_NETWORK_STATE, un permiso normal que trae una dependencia transitiva; está registrado como brecha aceptada.

Ojo. Declarar CAMERA sin necesitarlo tiene un costo. Si el manifiesto lo declara, Android obliga a pedirlo en tiempo de ejecución aunque uses el intent del sistema. Revisa la sección Android del README de cada plugin y declara solo lo que pide para tu caso.

2.4 Del adaptador a la pantalla

Qué hacer. El ViewModel (features/visitas/presentation/form/visita-form.view-model.ts) llama al caso de uso y traduce el resultado a un estado inmutable; la plantilla solo lo pinta. mensajeDeError convierte cualquier ErrorDominio (incluido PermisoDenegadoError) en el texto para la persona. Este es el método que atiende el botón:

  async tomarEvidencia(): Promise<void> {

      const evidencia = await this.capturarEvidencia.ejecutar();
      this.emitir({
        ...this.estado$.value,
        capturando: false,

        aviso: evidencia.aviso,

      this.emitir({ ...this.estado$.value, capturando: false, error: mensajeDeError(e) });

3. El caso de uso CapturarEvidencia y su prueba

La regla de negocio cabe en una línea: la foto es obligatoria y la ubicación es de mejor esfuerzo. El caso de uso la expresa sin saber que existe Capacitor, y por eso se puede probar en milisegundos con dobles escritos a mano.

Qué hacer. Escribe el caso de uso contra los puertos, un doble por puerto en src/testing/ y una prueba por cada rama de la regla.

import type { Camara } from '../../../../core/nativo/camara.port';
import { PermisoDenegadoError } from '../../../../core/nativo/permiso-denegado.error';
import type { Ubicacion } from '../../../../core/nativo/ubicacion.port';
import { Coordenadas } from '../visita';

export interface Evidencia {
  readonly foto: string;
  readonly ubicacion: Coordenadas | null;
  /** Mensaje para la persona cuando la ubicación no se pudo obtener. */
  readonly aviso: string | null;
}

export const AVISO_SIN_UBICACION = 'No se pudo obtener la ubicación; la visita se guarda sin coordenadas.';

/**
 * Caso de uso: capturar la evidencia de una visita.
 * - La FOTO es obligatoria: si la cámara falla (o se niega el permiso) el error se propaga.
 * - La UBICACIÓN es «mejor esfuerzo»: si falla, se conserva la foto y se devuelve un aviso.
 * Depende de los puertos Camara y Ubicacion, nunca de los plugins de Capacitor.
 */
export class CapturarEvidencia {
  constructor(
    private readonly camara: Camara,
    private readonly ubicacion: Ubicacion,
  ) {}

  async ejecutar(): Promise<Evidencia> {
    const foto = await this.camara.tomarFoto();
    try {
      return { foto, ubicacion: await this.ubicacion.obtenerActual(), aviso: null };
    } catch (e) {
      const aviso = e instanceof PermisoDenegadoError ? e.message : AVISO_SIN_UBICACION;
      return { foto, ubicacion: null, aviso };
    }
  }
}
import { Camara } from '../app/core/nativo/camara.port';
import { Coordenadas, Ubicacion } from '../app/core/nativo/ubicacion.port';

  constructor(private readonly resultado: string | Error) {}
  async tomarFoto(): Promise<string> {
    if (this.resultado instanceof Error) throw this.resultado;
    return this.resultado;
  }
}

export class UbicacionFalsa implements Ubicacion {
  constructor(private readonly resultado: Coordenadas | Error) {}
  async obtenerActual(): Promise<Coordenadas> {
    if (this.resultado instanceof Error) throw this.resultado;
    return this.resultado;
  }
}

4. Almacenamiento seguro de tokens y datos en reposo

El mínimo 5 exige los tokens en almacenamiento seguro. La referencia lo resuelve con el mismo patrón de la sección 1: un puerto (TokenStore), un adaptador sobre el plugin y un token de inyección con su factory.

Qué hacer.

npx cap sync android

Después escribe el puerto, el adaptador y el token que los une:

/** Par de tokens de la sesión (ver 03-api-y-datos/autenticacion.md). */
export interface TokensSesion {
  readonly accessToken: string;
  readonly refreshToken: string;
}

/**
 * Puerto: dónde se guardan los tokens. El resto de la app no sabe si es Keychain, Keystore o
 * memoria; las pruebas lo reemplazan por un doble en memoria (ADR-004).
 */
export interface TokenStore {
  leer(): Promise<TokensSesion | null>;
  guardar(tokens: TokensSesion): Promise<void>;
  borrar(): Promise<void>;
}
import { SecureStorage } from '@aparajita/capacitor-secure-storage';
import { TokenStore, TokensSesion } from './token-store.port';

const CLAVE = 'bitacora.sesion';

/**
 * Adaptador de TokenStore sobre @aparajita/capacitor-secure-storage:
 * iOS → Keychain; Android → AES-GCM con llave del Android Keystore.
 * En el navegador el plugin usa localStorage SIN cifrar: solo sirve para depurar (ADR-004).
 */
export class SecureTokenStore implements TokenStore {
  async leer(): Promise<TokensSesion | null> {
    const valor = await SecureStorage.get(CLAVE);
    return esTokensSesion(valor) ? valor : null;
  }

  async guardar(tokens: TokensSesion): Promise<void> {
    await SecureStorage.set(CLAVE, { accessToken: tokens.accessToken, refreshToken: tokens.refreshToken });
  }

  async borrar(): Promise<void> {
    await SecureStorage.remove(CLAVE);
  }
}
/** Puerto TokenStore → adaptador seguro por defecto. Las pruebas lo sobrescriben con un doble. */
export const TOKEN_STORE = new InjectionToken<TokenStore>('TOKEN_STORE', {
  providedIn: 'root',
  factory: () => new SecureTokenStore(),
});

esTokensSesion, al final de secure-token-store.ts, valida la forma del objeto leído: si no es un par de tokens, el adaptador responde null y la app pide login. Al cerrar sesión se borra todo lo local, tokens y caché, aunque no haya red para revocar el token en el servidor (core/sesion/sesion.service.ts):

  private async limpiarLocal(): Promise<void> {
    this.establecer(null);
    await Promise.all([this.tokenStore.borrar(), this.cache.limpiar()]);
  }

7.3 El keystore, con el script

Qué hacer. Crea la identidad de firma una sola vez:

py -3.11 scripts/crear_keystore.py

El script de la referencia hace cinco cosas, y conviene entenderlas antes de copiarlo:

  • Genera la contraseña con secrets.token_urlsafe(24) y nunca la imprime.
  • Se la pasa a keytool por variable de entorno (-storepass:env), así no queda en el historial de la terminal.
  • Crea android/app/bitacora-release.jks (PKCS12, RSA 4096, validez de 10 000 días, alias bitacora).
  • Escribe ruta, alias y contraseñas en android/keystore.properties, el único lugar donde quedan.
  • Se niega a regenerar un keystore existente: una llave nueva cambiaría la identidad de la app y la tienda rechazaría las actualizaciones.

Si keytool no está en el PATH (en Windows suele estar solo java), el script lo lanza como módulo de Java. Ninguno de los dos archivos entra al repositorio; estas líneas de android/.gitignore lo garantizan:

# Firma de release: NUNCA se versiona (ver docs/05-release/firma-y-tiendas.md)
keystore.properties
*.jks
*.keystore

Deberías ver. Que Git ignora los dos archivos y que ninguno está versionado:

Cuidado

El keystore y sus contraseñas nunca se muestran ni se versionan. No abran keystore.properties en una captura, no lo peguen en la memoria ni en un chat y no lo suban «para que el compañero compile». Respalden el .jks y la contraseña en dos lugares seguros (un gestor de secretos y una copia cifrada): si la llave se pierde, la app publicada no se puede volver a actualizar con la misma firma. Con Play App Signing esta llave es la llave de subida y Google custodia la de la app.

Nota. La referencia deja el .jks dentro de android/app/, ignorado por Git. Cumple la regla (fuera del control de versiones), pero vive en la carpeta del proyecto. Si prefieren sacarlo del árbol, storeFile en keystore.properties admite una ruta absoluta.

7.4 El signingConfig

Qué hacer. android/app/build.gradle lee las credenciales del archivo solo si existe. Sin él, el release sale sin firmar y la verificación del paso 7.6 lo detecta:

// Firma de release (docs/05-release/firma-y-tiendas.md). Las credenciales viven en
// android/keystore.properties, que crea scripts/crear_keystore.py y que NUNCA se versiona.
// Sin ese archivo el build de release sale sin firmar (y la verificación lo detecta).
def keystoreProps = new Properties()
def keystorePropsFile = rootProject.file('keystore.properties')
if (keystorePropsFile.exists()) {
    keystorePropsFile.withInputStream { keystoreProps.load(it) }
}
    signingConfigs {
        release {
            if (keystorePropsFile.exists()) {
                storeFile file(keystoreProps['storeFile'])
                storePassword keystoreProps['storePassword']
                keyAlias keystoreProps['keyAlias']
                keyPassword keystoreProps['keyPassword']
            }
        }
    }
    buildTypes {
        release {
            if (keystorePropsFile.exists()) {
                signingConfig signingConfigs.release
            }
            // R8 (minify) desactivado en v1.0.0: pendiente de probar en dispositivo con las reglas
            // de los plugins. Registrado como brecha en docs/05-release/checklist-release-v1.0.0.md.
            minifyEnabled false
            proguardFiles getDefaultProguardFile('proguard-android.txt'), 'proguard-rules.pro'
        }
    }

storeFile se resuelve respecto de android/app/, por eso en keystore.properties basta el nombre del .jks. En CI no hay archivo en disco: el .jks se guarda en base64 como secreto del repositorio y el job escribe keystore.properties antes de compilar.

7.8 R8: por qué es una brecha

R8 reduce, optimiza y ofusca el código nativo del APK. La referencia lo deja apagado (minifyEnabled false) y lo dice en el propio build.gradle: activarlo sin probar en dispositivo puede eliminar clases que los plugins cargan por reflexión, y la app fallaría al abrir la cámara o el almacenamiento seguro solo en release, donde nadie lo vio antes.

Por eso su checklist dice Go para pruebas internas y No-Go para producción. Para cerrarla: minifyEnabled true y shrinkResources true, compilar, repetir TC-04 y TC-05 en dispositivo con el APK de release y guardar el mapping.txt que genera R8 para leer las trazas de los fallos. Si su proyecto lo activa, esa evidencia va en la memoria; si no, va como brecha con su plan.
