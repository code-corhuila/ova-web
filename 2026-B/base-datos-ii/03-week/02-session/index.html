Vistas, CTE y consultas recursivas

Una consulta compleja no tiene por qué ser ilegible. Las CTE (WITH) dividen un problema grande en pasos con nombre; las vistas encapsulan lógica reutilizable y controlan el acceso; y las CTE recursivas recorren jerarquías (organigramas, categorías, grafos) que el SQL "plano" no puede. Escribir consultas mantenibles es tan importante como que devuelvan lo correcto.

1. CTE: dale nombre a cada paso

Nota

Una CTE (WITH nombre AS (...)) es una subconsulta con nombre que vive durante la consulta. Convierte una consulta anidada ilegible en una secuencia de pasos claros. No cambia el rendimiento por sí sola (el optimizador la integra), pero cambia radicalmente la mantenibilidad.

WITH ventas_cliente AS (
  SELECT id_cliente, SUM(total) AS gasto
  FROM factura GROUP BY id_cliente
),
promedio AS (
  SELECT AVG(gasto) AS media FROM ventas_cliente
)
SELECT v.id_cliente, v.gasto
FROM ventas_cliente v, promedio p
WHERE v.gasto > p.media;     -- clientes por encima del promedio, en pasos legibles

2. Vistas: encapsular y proteger

Tip

Una vista es una consulta guardada que se usa como si fuera una tabla: reutiliza lógica y controla acceso (expones solo ciertas columnas/filas). Una vista materializada guarda el resultado en disco (rápida de leer, pero hay que refrescarla): úsala para agregaciones caras que se consultan mucho y toleran cierto desfase.

3. CTE recursiva: recorrer jerarquías

WITH RECURSIVE cadena AS (
  SELECT id, nombre, jefe_id, 1 AS nivel
  FROM empleado WHERE jefe_id IS NULL          -- caso base (raíz)
  UNION ALL
  SELECT e.id, e.nombre, e.jefe_id, c.nivel + 1
  FROM empleado e JOIN cadena c ON e.jefe_id = c.id   -- paso recursivo
)
SELECT * FROM cadena ORDER BY nivel;

4. Un camino que enfrentarás en la vida real

Cuidado

Escenario — "el dashboard de totales tarda 30 s". Un panel ejecuta una agregación pesada (millones de filas) en cada carga. Normalizar la consulta no basta: el cálculo es intrínsecamente caro y se pide muchas veces con datos que cambian una vez al día. Fix: una vista materializada con el agregado, refrescada de noche (o tras la carga). Las consultas del panel pasan de 30 s a milisegundos. Trade‑off consciente: los datos tienen hasta 24 h de desfase, aceptable para ese panel. La vista materializada cambia "recalcular siempre" por "leer un resultado precomputado".

5. Errores comunes

  • Anidar subconsultas ilegibles en vez de usar CTE con nombres claros.
  • Creer que una vista "normal" acelera (no guarda resultado; se recalcula).
  • Olvidar refrescar una vista materializada → datos obsoletos.
  • CTE recursiva sin caso base o sin condición de término → recursión infinita.
