Programabilidad avanzada — funciones, procedimientos y lenguajes procedurales

Los motores modernos permiten programar lógica compleja dentro de la base de datos: funciones que devuelven valores o tablas, procedimientos que orquestan operaciones, y lenguajes procedurales (PL/pgSQL, PL/SQL) con variables, condicionales y bucles. Bien usado, esto acerca la lógica a los datos y reduce viajes de red; mal usado, esconde reglas de negocio difíciles de mantener.

1. Función vs procedimiento

Nota

Una función computa y devuelve un valor (o una tabla) y suele usarse dentro de consultas (SELECT mi_funcion(x)). Un procedimiento ejecuta acciones (puede no devolver nada), gestiona transacciones y se invoca (CALL). Regla: función para calcular; procedimiento para hacer (procesos, orquestación transaccional).

2. Lenguaje procedural: lógica en el servidor

-- Función table-valued: clientes en riesgo (gasto bajo su promedio histórico)
CREATE FUNCTION clientes_en_riesgo(umbral NUMERIC)
RETURNS TABLE(id_cliente BIGINT, gasto NUMERIC) AS $$
BEGIN
  RETURN QUERY
    SELECT f.id_cliente, SUM(f.total)
    FROM factura f
    GROUP BY f.id_cliente
    HAVING SUM(f.total) < umbral;
END;
$$ LANGUAGE plpgsql;
-- Se usa como una tabla:  SELECT * FROM clientes_en_riesgo(500000);

Tip

Los lenguajes procedurales (PL/pgSQL, PL/SQL, T‑SQL) añaden variables, IF/CASE, bucles y manejo de excepciones. Permiten encapsular cálculos complejos y reutilizarlos desde varias apps. Las funciones table‑valued (devuelven un conjunto) son especialmente útiles: se consultan como una tabla.

3. El equilibrio: ¿lógica en la BD o en la app?

Cuidado

Meter toda la lógica de negocio en la BD la vuelve difícil de versionar, testear y depurar (código repartido entre app y motor). Meter nada desperdicia la cercanía a los datos en procesos masivos. El criterio: lógica intensiva en datos y estable → BD; reglas de negocio cambiantes → aplicación.

4. Un camino que enfrentarás en la vida real

Cuidado

Escenario — "un cálculo trae 500.000 filas a la app para sumarlas". Un servicio descarga medio millón de registros por la red para calcular un total y unas categorías, tardando minutos y saturando memoria. Fix: una función/procedimiento que hace la agregación en el servidor y devuelve solo el resultado (unas filas). La red pasa de 500.000 filas a 10. Cuando el cálculo es intensivo en datos, muévelo a donde están los datos, no traigas los datos al cálculo.

5. Errores comunes

  • Usar un procedimiento donde bastaba una consulta/vista.
  • Meter reglas de negocio volátiles en la BD (difíciles de versionar/testear).
  • Traer datos masivos a la app para cálculos que el motor hace mejor.
  • Funciones con efectos secundarios ocultos usadas dentro de SELECT.
