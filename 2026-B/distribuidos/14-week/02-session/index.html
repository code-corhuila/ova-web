Planning — your pipeline, DoD-as-gates and branch protection

MVP 3 is next week. This planning session turns your Definition of Done into concrete, automated gates, defines the branch-protection rules that make those gates unavoidable, designs the pipeline for the whole system, and slices the CI/CD work — so the final release ships through a green, trustworthy pipeline.

1

Map each DoD item to an automated gate.

2

Define branch-protection rules per environment.

3

Design the pipeline for a multi-service system.

4

Slice CI/CD work into MVP 3 stories.

1. DoD becomes a checklist of machines

Note

Take your Definition of Done and, for each item, name the gate that proves it. If an item has no machine that can reject it, it's "self-certified" — a risk. The goal: every quality claim has a verifier.

2. Branch protection makes gates unavoidable

Note

Rules on the environment branches: no direct pushes, required status checks (the gates must be green), required review (at least one approval), and up-to-date with base. Now a change cannot reach develop/qa/main without passing — the discipline is enforced by the platform, not by trust.

3. Design the pipeline for many services

Tip

In a multi-repo product, each service has its own pipeline (build/test/scan/package its image). Use path filters so a change only runs the affected pipelines. Contract tests run cross-service. A shared release step promotes the tagged images to the next environment.

4. Slice the CI/CD stories

Note

MVP 3 stories, e.g.: "PRs to develop require green build+tests+lint (branch protection)"; "coverage gate fails under the floor"; "secret + dependency scan block on findings"; "merge to main builds and pushes a versioned image"; "a smoke test verifies the deployed system responds". Each with testable acceptance criteria.

5. A path you will face in real life

Caution

Scenario — "just merge it, the gate is being annoying." Under deadline pressure, someone disables a failing test and force-merges. The bug ships; trust in the pipeline erodes; soon everyone bypasses gates. Fix: gates are not optional — fix the cause, not the gate. Branch protection removes the bypass button; if a gate is wrong, fix the gate deliberately (reviewed), never skip it under pressure. A pipeline you bypass is theater.

6. Common mistakes

  • DoD items with no gate (self-certified, unenforced).
  • Optional/bypassable gates under deadline pressure.
  • One giant pipeline for everything (slow, no path filters).
  • Branch protection missing → direct pushes sneak past gates.
