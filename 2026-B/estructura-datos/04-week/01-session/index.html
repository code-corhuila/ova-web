Programación estructurada aplicada a estructuras de datos

Ya conoces arrays y listas; ahora aprenderás a manipularlas con código limpio y modular. La programación estructurada —secuencia, decisión, repetición y funciones— es la disciplina que hace tu código legible, reutilizable y fácil de depurar.

1

Aplicar secuencia, decisión y repetición sobre estructuras de datos.

2

Descomponer un problema en funciones/métodos con una sola responsabilidad.

3

Diseñar un programa modular basado en menú sobre un array o lista.

4

Escribir código legible siguiendo buenas prácticas.

1. Los tres pilares de la programación estructurada

Todo algoritmo se construye con tres estructuras de control:

  • Secuencia: instrucciones una tras otra.
  • Decisión: if / else, switch — el programa elige un camino.
  • Repetición: for, while — repetir mientras se cumpla una condición.

Nota

Con solo estas tres estructuras (más funciones) se puede escribir cualquier algoritmo. Es el teorema de la programación estructurada.

2. Modularidad: dividir para vencer

Un programa grande se vuelve inmanejable si es un solo bloque. La modularidad consiste en dividirlo en funciones (métodos), cada una con una sola responsabilidad y un nombre claro.

Sin modularidadCon modularidad
Un main giganteFunciones cortas y nombradas
Difícil de probarCada función se prueba sola
Código repetidoSe reutiliza llamando la función

Tip

Regla práctica: si no puedes describir lo que hace una función en una frase, probablemente hace demasiado y conviene dividirla.

3. Ejemplo: operaciones modulares sobre un array

static int sumar(int[] a) {
    int s = 0;
    for (int x : a) s += x;
    return s;
}
static int maximo(int[] a) {
    int m = a[0];
    for (int x : a) if (x > m) m = x;
    return m;
}
Scanner sc = new Scanner(System.in);
int[] datos = {10, 23, 7, 42, 15};
int op;
do {
    System.out.println("1) Sumar  2) Máximo  0) Salir");
    op = sc.nextInt();
    if (op == 1) System.out.println("Suma: " + sumar(datos));
    else if (op == 2) System.out.println("Máximo: " + maximo(datos));
} while (op != 0);

4. Buenas prácticas de código limpio

  • Nombres descriptivos (promedio, no p).
  • Una función = una tarea.
  • Evita "números mágicos"; usa constantes con nombre.
  • Comenta el porqué, no lo obvio.

Cuidado

Copiar y pegar el mismo bloque en varios lugares es una señal de alarma: extráelo a una función. Si cambias la lógica, solo la corriges en un sitio.
