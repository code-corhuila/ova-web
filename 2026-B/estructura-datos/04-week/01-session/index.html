Programación estructurada aplicada a estructuras de datos

Ya conoces arrays y listas; ahora aprenderás a manipularlas con código limpio y modular. La programación estructurada —secuencia, decisión y repetición, más la descomposición en funciones— es la disciplina que hace tu código legible, reutilizable y fácil de depurar.

1. El teorema de la programación estructurada

Nota

Teorema de Böhm-Jacopini (1966). Todo algoritmo computable puede escribirse combinando únicamente tres estructuras de control: secuencia, decisión (selección) y repetición (iteración). No se necesita goto.

EstructuraQué haceEn Java
SecuenciaInstrucciones una tras otraa; b; c;
DecisiónElige un camino según una condiciónif / else, switch
RepeticiónRepite mientras se cumpla una condiciónfor, while, do-while
Secuencia      Decisión            Repetición
  |             /  \                  +--<--+
  A            V    V                 |     |
  |          [sí] [no]            [cond?]--sí--> cuerpo
  B                                   |no
                                      v

Nota

Cada estructura tiene una sola entrada y una sola salida. Respetarlo hace el flujo predecible y fácil de razonar (y de depurar).

2. Modularidad: descomponer en funciones

Un programa grande en un solo bloque es inmanejable. La modularidad lo divide en funciones (métodos), cada una con una responsabilidad y un nombre claro.

Sin modularidadCon modularidad
Un main giganteFunciones cortas y nombradas
Difícil de probarCada función se prueba por separado
Código repetidoSe reutiliza llamando a la función

Dos criterios de calidad al dividir:

  • Cohesión (alta): cada función se concentra en una tarea relacionada.
  • Acoplamiento (bajo): las funciones dependen poco entre sí; se comunican por parámetros y valores de retorno, no por variables globales.

Tip

Regla práctica: si no puedes describir lo que hace una función en una frase, probablemente hace demasiado y conviene dividirla.

3. Ejemplo: operaciones modulares sobre un array

static int sumar(int[] a) {
    int s = 0;
    for (int x : a) s += x;
    return s;
}
static double promedio(int[] a) {
    return a.length == 0 ? 0 : (double) sumar(a) / a.length;
}
static int maximo(int[] a) {
    int m = a[0];
    for (int x : a) if (x > m) m = x;
    return m;
}
Scanner sc = new Scanner(System.in);
int[] datos = {10, 23, 7, 42, 15};
int op;
do {
    System.out.println("1) Sumar  2) Promedio  3) Máximo  0) Salir");
    op = sc.nextInt();
    switch (op) {
        case 1 -> System.out.println("Suma: " + sumar(datos));
        case 2 -> System.out.println("Promedio: " + promedio(datos));
        case 3 -> System.out.println("Máximo: " + maximo(datos));
    }
} while (op != 0);

Nota

promedio reutiliza sumar: DRY (no repetir la lógica). Un cambio en cómo se suma se corrige en un solo lugar.

4. Buenas prácticas de código limpio

  • Nombres descriptivos (promedio, no p); métodos con verbo, valores con sustantivo.
  • Una función = una tarea.
  • Evita números mágicos; usa constantes con nombre.
  • Comenta el porqué, no lo obvio.
  • Prefiere parámetros y retorno a variables globales compartidas.

Cuidado

Copiar y pegar el mismo bloque en varios lugares es una señal de alarma: extráelo a una función. Si cambias la lógica, solo la corriges en un sitio.

5. Errores comunes

  • Un main que hace todo (baja cohesión) → difícil de probar y leer.
  • Funciones que dependen de variables globales (alto acoplamiento).
  • Duplicar lógica en vez de extraer una función.
  • Bucles con condiciones de salida poco claras o múltiples return desordenados.
