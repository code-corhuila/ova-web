Gestión de datos con estructuras

Llevemos todo a la práctica construyendo un sistema que da de alta, lista, busca, actualiza y elimina datos. Verás cómo la estructura elegida moldea el costo de cada operación de un CRUD real y cómo una clave única cambia por completo la eficiencia de la búsqueda.

1

Definir el CRUD y el costo de cada operación por estructura.

2

Elegir la estructura según la operación dominante del sistema.

3

Implementar un CRUD con lista y otro con mapa (clave única).

4

Mantener invariantes de integridad (claves únicas, validación).

1. Gestionar datos = CRUD

Nota

CRUD. Las cuatro operaciones básicas sobre una colección de datos: Create (alta), Read (leer/listar/buscar), Update (actualizar) y Delete (baja). Casi todo sistema de información se reduce a combinarlas.

Nota

La estructura que elijas define qué tan eficiente es cada letra del CRUD. El mismo sistema se siente rápido o lento según esa decisión de diseño.

2. Costo del CRUD según la estructura

OperaciónLista/ArrayABB equilibradoMapa (hash)
Create (alta)O(1) al finalO(log n)O(1) prom.
Read (buscar por clave)O(n)O(log n)O(1) prom.
Update (localizar + cambiar)O(n)O(log n)O(1) prom.
Delete (por clave)O(n)O(log n)O(1) prom.
Listar en ordenO(n) tras ordenarO(n) inordenNo ordenado

Nota

Si el sistema busca por clave con muchísima frecuencia, un mapa (clave → valor) convierte esas búsquedas O(n) en O(1) promedio. Es la diferencia entre un sistema que escala y uno que se arrastra.

3. Ejemplo: gestión de estudiantes

Primero analiza qué operación domina:

OperaciónFrecuenciaEstructura que ayuda
Registrar (alta)AltaLista / mapa
Listar todosMediaLista o array
Buscar por códigoMuy altaMapa o ABB
EliminarBajaMapa (por clave) o lista

4. CRUD con lista (búsqueda O(n))

class Estudiante {
    int codigo; String nombre;
    Estudiante(int c, String n) { codigo = c; nombre = n; }
}
List<Estudiante> lista = new ArrayList<>();
lista.add(new Estudiante(101, "Ana"));   // Create
lista.add(new Estudiante(102, "Luis"));
Estudiante buscar(int cod) {              // Read: O(n)
    for (Estudiante e : lista)
        if (e.codigo == cod) return e;
    return null;
}
Estudiante e = buscar(102);
if (e != null) e.nombre = "Luis A.";      // Update
lista.removeIf(x -> x.codigo == 101);     // Delete: O(n)

5. CRUD con mapa (búsqueda O(1) por clave)

Map<Integer, Estudiante> mapa = new HashMap<>();
mapa.put(101, new Estudiante(101, "Ana"));    // Create
mapa.put(102, new Estudiante(102, "Luis"));

Estudiante e = mapa.get(102);                 // Read: O(1) prom.
if (e != null) e.nombre = "Luis A.";          // Update
mapa.remove(101);                             // Delete: O(1) prom.

Nota

La clave (el código) debe ser única: es la invariante de integridad. map.put con una clave existente reemplaza el valor anterior, lo que sirve tanto para crear como para actualizar.

6. Del problema a la estructura (método)

  1. Lista las operaciones del sistema.
  2. Marca la que se ejecuta con más frecuencia.
  3. Elige la estructura que haga esa operación más barata.
  4. Verifica que las demás operaciones sigan siendo aceptables.

Cuidado

Buscar en una lista es O(n): recorre uno por uno. Si el sistema busca millones de veces, ese O(n) se nota. Ahí un mapa o un ABB marcan la diferencia.

7. Errores comunes

  • Usar una lista y buscar por clave millones de veces (O(n) evitable con un mapa).
  • No garantizar la unicidad de la clave → datos duplicados o ambiguos.
  • No validar la entrada al dar de alta (código negativo, nombre vacío).
  • Elegir la estructura por costumbre y no por la operación dominante.
