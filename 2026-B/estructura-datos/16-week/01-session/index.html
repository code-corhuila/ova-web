Retroalimentación, ajustes del proyecto y cierre

Última semana. Presentamos el proyecto, recibimos retroalimentación, hacemos los ajustes finales y miramos atrás para consolidar todo lo aprendido en el semestre.

Consolidar el mapa completo del curso.

1. Presentación del proyecto

Cada estudiante (o equipo) presenta su proyecto en pocos minutos, enfocándose en:

  • El problema y las estructuras elegidas.
  • La justificación de cada elección.
  • El análisis de complejidad de las operaciones clave.
  • Una demostración breve del CRUD funcionando.

Tip

No narres línea por línea el código: explica decisiones. "Usé una cola aquí porque…" vale más que leer métodos.

2. Retroalimentación → ajustes

La retroalimentación solo sirve si se convierte en cambios. Anota y aplica:

  • Correcciones de uso de estructuras señaladas por el docente/compañeros.
  • Mejora del README (claridad del análisis Big-O).
  • Casos borde faltantes o errores detectados en la demo.
  • Limpieza final del repositorio (commits claros).

4. Y ahora, ¿qué sigue?

Las estructuras de datos son la base de casi todo lo que viene: análisis de algoritmos, bases de datos, inteligencia artificial y el desarrollo profesional. Lo que dominaste este semestre te acompañará en toda la carrera.
