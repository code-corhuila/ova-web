Pilas (Stack)

La pila es una estructura tan simple como poderosa. Sigue una única regla —el último en entrar es el primero en salir— y con ella se resuelven desde el botón "deshacer" hasta la propia ejecución de tus programas. Aquí la definimos con precisión, la implementamos de dos formas y resolvemos un problema clásico.

1. Definición y principio LIFO

Nota

Pila (stack). Estructura lineal en la que los elementos se insertan y se extraen por un solo extremo, el tope (top). Cumple la política LIFO (Last In, First Out): el último en entrar es el primero en salir.

Nota

Piensa en una pila de platos: solo pones o quitas el de arriba. Nunca sacas uno del medio.

2. La pila como TAD

OperaciónQué hacePrecondiciónCosto
push(x)Inserta x en el tope— (o no lleno)O(1)
pop()Quita y devuelve el topepila no vacíaO(1)
peek()Devuelve el tope sin quitarlopila no vacíaO(1)
isEmpty()¿Está vacía?—O(1)
size()Número de elementos—O(1)

Todas son O(1): operar en el tope no depende del tamaño.

push(3)      push(7)      pop() -> 7   peek() -> 3
 | 3 |        | 7 |<-tope   | 3 |<-tope  (3 sigue)
 +---+        | 3 |         +---+
              +---+

3. Dos condiciones de error

Cuidado

Underflow: hacer pop() o peek() en una pila vacía. Overflow: hacer push() en una pila llena (solo en la implementación con array de tamaño fijo). Verifica siempre antes de operar.

4. Implementación en Java

Deque<Integer> pila = new ArrayDeque<>();
pila.push(3);
pila.push(7);
System.out.println(pila.peek()); // 7
System.out.println(pila.pop());  // 7
System.out.println(pila.isEmpty()); // false
class Pila {
    private int[] datos = new int[100];
    private int tope = -1;              // -1 = vacía
    void push(int x) {
        if (tope == datos.length - 1) throw new IllegalStateException("overflow");
        datos[++tope] = x;
    }
    int pop() {
        if (isEmpty()) throw new IllegalStateException("underflow");
        return datos[tope--];
    }
    int peek() { if (isEmpty()) throw new IllegalStateException(); return datos[tope]; }
    boolean isEmpty() { return tope == -1; }
    int size() { return tope + 1; }
}
class Pila {
    private Nodo tope;                  // null = vacía
    private static class Nodo { int dato; Nodo sig; Nodo(int d){dato=d;} }
    void push(int x) { Nodo n = new Nodo(x); n.sig = tope; tope = n; }
    int pop() { int x = tope.dato; tope = tope.sig; return x; }
    boolean isEmpty() { return tope == null; }
}

Nota

Con array el tamaño es fijo (posible overflow) pero la memoria es compacta. Con nodos crece dinámicamente sin overflow, a costa de una referencia por elemento. Ambas dan push/pop en O(1).

5. Aplicaciones

  • Deshacer/rehacer (undo/redo) en editores.
  • Historial del navegador (botón "atrás").
  • Pila de llamadas (call stack): la JVM apila cada llamada a método.
  • Evaluar expresiones y verificar paréntesis balanceados.
  • Base de recorridos DFS (profundidad) en grafos/árboles.

6. Problema clásico: paréntesis balanceados

Recorres el texto: cada símbolo de apertura hace push; en cada cierre haces pop y verificas que el tope corresponda.

boolean balanceado(String s) {
    Deque<Character> p = new ArrayDeque<>();
    for (char c : s.toCharArray()) {
        if (c == '(' || c == '[' || c == '{') p.push(c);
        else if (c == ')') { if (p.isEmpty() || p.pop() != '(') return false; }
        else if (c == ']') { if (p.isEmpty() || p.pop() != '[') return false; }
        else if (c == '}') { if (p.isEmpty() || p.pop() != '{') return false; }
    }
    return p.isEmpty();   // deben haberse cerrado todas
}

Tip

Si al terminar la pila no está vacía, quedaron aperturas sin cerrar → no está balanceado. Si intentas cerrar con la pila vacía, hay un cierre de más.

7. Errores comunes

  • Hacer pop/peek sin comprobar isEmpty() (underflow → excepción).
  • En la versión con array, olvidar el chequeo de overflow.
  • Confundir peek (mira) con pop (quita).
  • Usar una pila cuando el problema pide orden FIFO (eso es una cola, Semana 7).
