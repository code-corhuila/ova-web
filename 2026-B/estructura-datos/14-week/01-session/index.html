Introducción a la eficiencia (notación Big-O)

Dos programas resuelven lo mismo, pero uno tarda un segundo y el otro una hora. La notación Big-O es el lenguaje para medir y comparar ese costo sin depender del computador. Dominarla es lo que separa a un programador de un ingeniero.

1

Definir Big-O como cota asintótica del peor caso.

2

Aplicar las reglas para simplificar la complejidad.

3

Reconocer y estimar O(1), O(log n), O(n), O(n log n) y O(n²).

1. ¿Por qué medir la eficiencia?

El tiempo en segundos depende del computador. Necesitamos una medida independiente del hardware: cuántas operaciones hace el algoritmo en función del tamaño de la entrada `n`. Eso es la complejidad.

Nota

Notación Big-O. Describe una cota superior del crecimiento del costo cuando n tiende a infinito. O(f(n)) significa que, para n grande, el costo crece a lo sumo como f(n). Por convención expresa el peor caso.

2. Reglas para simplificar

ReglaEjemploResultado
Se ignoran las constantesO(2n)O(n)
Se conserva el término dominanteO(n² + n)O(n²)
Los pasos en secuencia se suman (domina el mayor)O(n) + O(n²)O(n²)
Los bucles anidados se multiplicanO(n) · O(n)O(n²)

Nota

Big-O ignora constantes y términos menores porque, para n grande, el término dominante decide. Un O(n²) siempre superará a un O(n) si n crece lo suficiente.

Cuidado

O(n²) crece muy rápido: con n = 1.000 son un millón de operaciones; con n = 1.000.000, un billón. Evítalo cuando la entrada pueda ser grande.

5. ¿Cómo se estima?

  • Una instrucción simple → O(1).
  • Un bucle que recorre n elementos → O(n).
  • Un bucle dentro de otro → O(n²).
  • Dividir el problema a la mitad en cada paso → O(log n).
int suma = 0;
for (int i = 0; i < n; i++) suma += a[i];   // un bucle: O(n)
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++)             // bucle dentro de bucle: O(n^2)
        if (a[i] == a[j]) cuenta++;
int lo = 0, hi = n - 1;
while (lo <= hi) {                          // descarta la mitad cada vez
    int mid = (lo + hi) / 2;
    if (a[mid] == x) return mid;
    else if (a[mid] < x) lo = mid + 1;
    else hi = mid - 1;
}

6. Peor, mejor y caso promedio

Una búsqueda lineal encuentra el dato en el primer intento (mejor caso, O(1)) o en el último (peor caso, O(n)). Big-O reporta normalmente el peor caso porque es la garantía que podemos ofrecer.

7. Complejidad espacial

Big-O también mide memoria: un algoritmo que copia el arreglo usa O(n) de espacio; uno que solo usa unas variables, O(1). A veces se cambia más memoria por menos tiempo (y viceversa).

Elegir bien la estructura (Semana 11) es, en el fondo, elegir una mejor Big-O.

9. Errores comunes

  • Dejar constantes o términos menores (escribir O(2n+3) en vez de O(n)).
  • Sumar bucles anidados en vez de multiplicarlos.
  • Confundir el mejor caso con la complejidad (que reporta el peor).
  • Olvidar la complejidad espacial al comparar soluciones.
