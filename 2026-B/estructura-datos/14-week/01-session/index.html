Introducción a la eficiencia (notación Big-O)

Dos programas resuelven lo mismo, pero uno tarda un segundo y el otro una hora. La notación Big-O es el lenguaje para medir y comparar ese costo sin depender del computador. Es lo que separa a un programador de un ingeniero.

1. ¿Por qué medir la eficiencia?

El tiempo en segundos depende del computador. Necesitamos una medida independiente del hardware: cuántas operaciones hace el algoritmo en función del tamaño de la entrada (n). Eso es la complejidad, y se expresa con la notación Big-O.

Nota

Big-O describe cómo crece el costo cuando n crece. Nos interesa el comportamiento para n grande, no los detalles pequeños.

3. ¿Cómo se estima?

  • Una instrucción simple → O(1).
  • Un bucle que recorre n elementos → O(n).
  • Un bucle dentro de otro bucle → O(n²).
  • Dividir el problema a la mitad en cada paso → O(log n).
int suma = 0;
for (int i = 0; i < n; i++) suma += a[i];   // un bucle: O(n)
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++)             // bucle dentro de bucle: O(n^2)
        if (a[i] == a[j]) cuenta++;

Cuidado

O(n²) crece muy rápido: con n = 1.000 son un millón de operaciones; con n = 1.000.000, un billón. Evítalo cuando la entrada pueda ser grande.

4. La estructura decide la complejidad

La estructura elegida cambia la Big-O de tus operaciones:

OperaciónArray/ListaEstructura de búsqueda
Buscar un elementoO(n)O(log n)
Acceder por índiceO(1) (array)—
Insertar al inicioO(1) (lista)O(log n)

Tip

Por eso el curso completo tiene sentido aquí: elegir bien la estructura (Semana 11) es, en el fondo, elegir una mejor Big-O.
