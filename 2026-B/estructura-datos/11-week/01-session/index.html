Comparación de estructuras de datos

Ya conoces arrays, listas, pilas, colas y árboles. La habilidad profesional no es conocerlas, sino saber CUÁL usar en cada situación. Esta sesión reúne los costos de todas en una sola tabla y te da un criterio de decisión con fundamento.

1

Comparar todas las estructuras por costo de sus operaciones.

2

Aplicar un árbol de decisión para elegir estructura.

3

Justificar la elección según la operación dominante y la memoria.

4

Reconocer que las soluciones reales combinan estructuras.

1. La pregunta correcta

No existe "la mejor estructura": existe la mejor para la operación dominante. Antes de elegir pregúntate: ¿qué operación haré con más frecuencia? — acceder por posición, insertar/eliminar, buscar, o mantener orden.

Nota

Elegir bien la estructura suele importar más que optimizar el código: convierte un algoritmo O(n) en uno O(1) o O(log n). Es una decisión de diseño, no de detalle.

La tabla hash (mapa) aparece como preview: da búsqueda/inserción O(1) promedio por clave, pero no mantiene orden. La estudiarás a fondo con Map en cursos/temas posteriores.

3. Árbol de decisión

¿Acceso inmediato por posición y tamaño fijo?        -> ARRAY
¿Muchas inserciones/eliminaciones, tamaño variable?  -> LISTA ENLAZADA
¿"El último que entró sale primero"?                 -> PILA (LIFO)
¿"El primero que entró sale primero"?                -> COLA (FIFO)
¿Buscar rápido MANTENIENDO orden?                    -> ABB / árbol de búsqueda
¿Buscar por clave sin importar el orden?             -> TABLA HASH (Map)

Tip

Muchas soluciones combinan estructuras: una cola de tareas donde cada tarea contiene una lista, o un árbol cuyos nodos se recorren con una cola (BFS).

5. No olvides la memoria

Elegir también implica espacio: una lista o un árbol pagan enlaces extra por nodo; un array es compacto pero de tamaño fijo; una tabla hash reserva espacio adicional para dispersar. La estructura correcta equilibra tiempo y memoria según el caso.

6. Errores comunes

  • Elegir por costumbre y no por la operación dominante.
  • Ignorar el costo de memoria (solo mirar el tiempo).
  • Usar un array ordenado y luego insertar mucho en medio (cada inserción O(n)).
  • Suponer que un ABB es O(log n) aunque esté degenerado (sería O(n)).
